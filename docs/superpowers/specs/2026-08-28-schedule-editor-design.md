# 일정 편집기 — 설계

2026-08-28 · 대상 `index.html` (제주 가족여행 안내 웹앱)

---

## 1. 무엇을 만드나

**앱 안에서 일정의 시각·머무는 시간·장소·순서를 고치면, 이동시간이 자동으로 계산되어
뒤 일정이 따라 움직이고, 무리한 곳에 경고가 붙는 편집기.**

지금은 일정이 코드에 박혀 있어 고치려면 파일을 직접 손봐야 한다. 시각을 하나 바꾸면
뒤 일정을 손으로 다시 계산해야 하고, 계산이 맞는지도 확인할 길이 없다.

## 2. 정해진 것

브레인스토밍에서 사용자가 고른 것들이다. 되돌리려면 이유가 있어야 한다.

| 갈림길 | 정한 것 | 이유 |
|---|---|---|
| 편집자 | **나 혼자.** 결과는 코드로 내보내 배포 | 가족은 늘 완성된 일정만 본다. 단일 파일 전제가 유지되고, 부모님이 실수로 일정을 바꿔 놓을 위험이 없다 |
| 재계산 | **순서대로 쌓아 올리기** | 출발 시각과 머무는 시간만 정하면 나머지 시각이 자동으로 나온다 |
| 장소 선택 | **등록된 99곳 검색 + 직접 입력** | 여행지 48·맛집 51 은 좌표가 이미 있어 고르면 이동시간이 바로 계산된다. 휴게소·숙소처럼 목록에 없는 곳은 이름만 고친다 |
| 편집 범위 | 시각 · 머무는 시간 · 장소 · **순서** · **추가/삭제** | 트리플 같은 여행앱 수준으로 |
| 진입 | **범례 줄 끝의 작은 `#`** | 가족에게는 장식으로 보인다. 화면에 잡물을 안 둔다는 원칙과 부딪히지 않는다 |
| 경고 | 식사 타이밍 · 문 닫힌 시간·휴무일 · 배 시간 | 앱에 이미 운영시간·휴무일·영업시간 자료가 있다 |

## 3. 화면

### 3.1 들어가고 나오기

범례 줄 오른쪽 끝에 작은 `#`. 누르면 일정 탭이 편집 화면으로 바뀐다.

편집 중에는 목록 위에 얇은 띠가 붙는다.

```
편집 중 · 3일차          [원래대로] [코드 복사] [닫기]
```

- **원래대로** — 저장된 편집을 지우고 배포된 일정으로 완전히 되돌린다.
  부모님이 실수로 눌렀을 때의 탈출구다.
- **코드 복사** — 바뀐 내용을 `D` 배열에 넣을 형태로 클립보드에 담는다.
- **닫기** — 편집 내용은 남긴 채 보기 화면으로.

### 3.2 편집 중인 정차지 카드

```
┌─────────────────────────────────────┐
│ ⠿  [09:00]  성산일출봉          ✕  │   ⠿ 끌기 손잡이 · ✕ 빼기
│    머무는 시간 [ 90 ]분   [↑] [↓]   │
└─────────────────────────────────────┘
        🚗 25분 · 18.3km        [+]      ← 이동시간 칩과 넣기 버튼
┌─────────────────────────────────────┐
│ ⠿  [10:55]  광치기해변          ✕  │
```

- **시각** — 직접 고칠 수 있다. 고치면 그 정차지가 새 기준점이 되어 뒤가 다시 계산된다.
- **머무는 시간** — 분 단위. 고치면 그 뒤 전부 다시 계산된다.
- **장소 이름** — 누르면 검색창이 열린다(§4.3).
- **순서** — 끌기(⠿)와 화살표(↑↓) 둘 다. 휴대폰에서 드래그가 스크롤과 엉키는 일이 잦아
  화살표를 함께 둔다.
- **이동시간 칩** — 정차지 사이에 자동차 소요시간과 거리. 여기 `+` 로 새 장소를 끼운다.

## 4. 시간 계산

### 4.1 자료에 새로 넣는 것

| 필드 | 뜻 | 초기값 |
|---|---|---|
| `stay` | 그 장소에 머무는 분 | 기존 시각 차이에서 이동시간을 뺀 값으로 자동으로 채운다 |
| `fix` | 이 시각은 못 박음 (`true`/없음) | 1일차 `진도항 도착` 처럼 배를 **타는** 정차지에 붙인다. 내리는 쪽은 안 붙인다 |
| `pk` | 주차장 좌표 `[위도, 경도]` — 길찾기의 출발·도착점 | `SPOT` 48곳 중 33곳에 붙인다. 없는 곳은 `ll` 을 그대로 쓴다 (§4.3.1) |

`pk` 는 `ll` 을 대신하지 않고 나란히 둔다. `ll` 은 지도에 점을 찍는 자리이고 `pk` 는
차가 서는 자리다. 오름은 이 둘이 수백 미터 떨어져 있다.

`fix` 는 편집 카드에서 켜고 끌 수 있어야 한다. 숙소 체크인 마감처럼 배 말고도
못 박을 것이 생기기 때문이다. 켜면 시각 칸이 잠기고, 계산 결과가 그보다 늦으면 §5.3 경고가 붙는다.

`stay` 를 자동으로 채우는 이유 — 지금 자료에는 시각만 있다. 정차지 A 가 11:05,
B 가 13:30 이고 그 사이 이동이 25분이면 A 의 `stay` 는 120분이다. 이렇게 하면
편집기를 처음 열었을 때 계산 결과가 **지금 일정과 똑같이** 나온다. 값이 갑자기
바뀌면 무엇이 내 편집이고 무엇이 계산 오차인지 알 수 없다.

### 4.2 계산 순서

하루 안에서 첫 정차지 시각을 기준으로 순서대로 쌓는다.

```
출발[0] = 첫 정차지 시각 (고치면 그 값이 기준)
도착[n] = 출발[n-1] + 이동시간(n-1 → n)
출발[n] = 도착[n] + stay[n]
```

좌표가 없는 정차지(휴게소·체크아웃 등, 52곳 중 22곳)는 이동시간을 계산할 수 없다.
**그 구간의 이동시간을 0 으로 두고 `stay` 만 더한다.** 즉 배포판 시각 차이가
`stay` 로 흡수되어 계산 결과가 지금과 같아진다.

시각을 직접 고치면 그 정차지부터 새 기준으로 다시 쌓는다. 앞쪽은 건드리지 않는다.

### 4.3 이동시간을 어디서 얻나

**카카오 길찾기(카카오모빌리티 Directions)의 소요시간.** 2026-08-28 에 OSRM 에서 바꿨다.

발급한 REST API 키로 `https://apis-navi.kakaomobility.com/v1/directions` 를 부른다.
`hanbrook3.github.io` 원본에서 브라우저 fetch 가 그대로 통한다(CORS 열려 있음, 2026-08-28 확인).

**키는 코드에 넣지 않는다.** REST 키는 JavaScript 키와 달리 도메인 제한이 없어, 저장소에
노출되면 남이 그대로 가져다 쓸 수 있다. 편집기에 처음 들어올 때 한 번 붙여넣게 하고
브라우저에만 남긴다. 편집자는 나 혼자이고 가족은 편집기를 쓰지 않으므로 이걸로 충분하다.
배포되는 일정에는 계산이 끝난 시각만 들어간다.

#### 왜 OSRM 을 안 쓰나

OSRM 의 시간은 도로 등급과 제한속도 태그로 **전처리 때 미리 구워둔 속도표**를 거리로 나눈
값이다. 실시간 정체도 시간대도 신호 대기도 모르는 자유주행 시간이다. 공개 데모 서버
(`router.project-osrm.org`)의 사용 정책도 초당 1회·비상업·가벼운 사용으로 한정돼 있고,
가동률과 자료 갱신을 보장하지 않으며 예고 없이 차단할 수 있다고 명시돼 있다.

같은 여섯 구간을 카카오로 다시 재봤다 (2026-08-28):

| 구간 | OSRM | 카카오 |
|---|---|---|
| 협재 → 함덕 | 47.7km · 55분 | 56.5km · 69분 |
| 제주항 → 남원 숙소 | 39.3km · 47분 | 33.9km · 47분 |
| 사려니 → 비자림 | 20.8km · 29분 | 21.0km · 29분 |
| 산방산 → 오설록 | 9.2km · 11분 | 9.3km · 15분 |
| 성산일출봉 → 천지연폭포 | 48.3km · 55분 | 좌표 거부 |
| 성산일출봉 → 섭지코지 | 6.1km · 11분 | 좌표 거부 |

중간 거리는 사실상 같고 짧은 구간에서 카카오가 몇 분 더 본다. 카카오가 일률적으로 더
정확한 것이 아니라 **다른 경로를 고른다.** 바꾸는 이유는 정확도 우위가 아니라, 남의 데모
서버에 기대지 않는 것과 아래 주차장 좌표를 함께 쓰기 위해서다.

#### 4.3.1 좌표는 주차장 기준으로

**카카오는 좌표가 도로에서 멀면 계산을 거부한다** (`result_code 102` "시작 지점 주변의
도로를 탐색할 수 없음"). 등록된 99곳을 전수 조사하니 **성산일출봉과 한라생태숲** 두 곳이
걸렸다. 나머지 97곳은 카카오가 가장 가까운 도로를 잡는다.

그런데 도로를 잡는 것과 차가 실제로 서는 곳은 다르다. 오름은 정상이, 해변은 한가운데가
등록돼 있어 이동시간이 주차장까지가 아니라 엉뚱한 지점까지로 계산된다. 그래서
**여행지 48곳에 주차장 좌표를 따로 붙인다.**

**`ll` 은 건드리지 않고 새 항목을 더한다.** `ll` 은 지도에 점을 찍는 데도 쓰이므로
주차장으로 덮어쓰면 오름 정상 대신 주차장에 점이 찍힌다. 지도 표시는 `ll`, 길찾기는
새 항목을 쓴다.

카카오 장소 검색으로 "{이름} 주차장" 을 찾은 결과 (2026-08-28, 여행지 48곳 기준):
| | 곳 |
|---|---|
| 주차장 좌표를 붙인 곳 | 33 |
| 주차장 POI 가 없어 등록 좌표를 그대로 쓰는 곳 | 14 |
| 등록 좌표 자체가 틀린 곳 | 1 |

결과는 `tools/parking-coords.tsv` 에 있다.

붙인 33곳 중 등록 좌표에서 300m~1km 떨어진 곳이 여럿인데, 오름·폭포처럼 주차장이 아래에
있는 곳이라 먼 것이 정상이다(한라생태숲 1,111m · 비자림 881m · 천지연폭포 669m ·
따라비오름 517m).

주차장이 없는 14곳은 미술관·해변·도로다. 유민미술관과 글라스하우스는 섭지코지 주차장을
같이 쓰고, 5.16도로 숲터널과 형제해안도로는 도로 자체라 주차장이라는 개념이 없다.
알뜨르비행장은 너른 들판이라 전용 주차장이 없고, 이호테우해변은 등록 좌표가 이미
해수욕장에서 75m 안이다. **이런 곳은 등록 좌표를 그대로 쓴다** — 어차피 길찾기가 되는
곳들이다.

**외돌개는 등록 좌표가 틀렸다.** `ll:[33.24, 126.51]` 인데 카카오가 아는 외돌개는
(33.2390, 126.5449) 로 **3.2km 떨어져 있다.** 지금 지도에 외돌개 점이 엉뚱한 곳에
찍히고 있다는 뜻이다. HANDOVER 의 제주둥지 991m 사례와 같은 종류다. 주차장은
외돌개주차장(33.2412, 126.5475). **이건 길찾기와 별개로 `ll` 을 고쳐야 하는 건이라
따로 판단한다.**

- 좌표쌍 단위로 캐시한다. 같은 구간을 두 번 묻지 않는다.
- **키가 없거나 인터넷이 없으면 직선거리로 추정한다.** 계산이 멈추면 편집기 자체가
  못 쓰게 되므로 폴백이 필요하다. 계수는 위 실측으로 맞춘다.
- 카카오도 **주차하고 걸어 들어가는 시간은 세지 않는다.** 여유를 얹을지는 실제로 써 보고
  정한다 — 처음부터 임의의 값을 더하면 어디까지가 실제 값인지 알 수 없게 된다.
- 무료 쿼터는 자동차 길찾기 10,000건/일, 장소 검색 100,000건/일. 편집 한 번에 많아야
  수십 건이라 넉넉하다.

### 4.4 하루 요약 배너

`D[i].st` 가 시각을 담고 있다. 재계산하면 여기 시각도 함께 갱신해야 한다.
안 그러면 배너와 목록이 서로 다른 시간을 말한다.

날마다 세 항목인데 **가운데 항목이 날마다 다르다.**

```
1일차 [['05:40','대소 출발'], ['385km','4시간 45분'], ['17:45','숙소 도착']]
5일차 [['08:20','숙소 출발'], ['11:00','제주 출항'],  ['18:50','대소 도착']]
```

1~4일차는 가운데가 거리이고 5일차는 시각이다. 그러므로 **첫 값이 `HH:MM` 형식인
항목만 갱신하고 나머지는 그대로 둔다.** 첫 항목은 그날 첫 정차지 시각,
마지막 항목은 마지막 정차지 시각으로 맞춘다. 가운데가 시각이면 이름이 같은
정차지를 찾아 그 시각을 쓴다.

## 5. 경고

계산이 끝난 뒤 하루 전체를 훑어 붙인다. 정차지 카드 아래에 문장으로 보여준다.

### 5.1 식사 타이밍

`ty:'meal'` 인 정차지의 도착 시각이 아래를 벗어나면 알린다.

| 끼니 | 알맞은 시간대 |
|---|---|
| 아침 | 06:30 ~ 09:30 |
| 점심 | 11:30 ~ 14:00 |
| 저녁 | 17:30 ~ 20:00 |

어느 끼니인지는 **배포판에 적힌 원래 시각**으로 한 번만 판정하고 편집 중에 바뀌지 않는다
(11시 전이면 아침, 15시 전이면 점심, 나머지는 저녁). 계산된 시각으로 판정하면
점심을 16시로 밀었을 때 "저녁이 이르다"로 바뀌어 경고가 뒤집힌다.

> ※ 점심이 오후 3시 20분입니다. 너무 늦습니다.

### 5.2 문 닫힌 시간 · 휴무일

정차지 이름이 `SPOT` 에 있으면 그 자료의 운영시간·휴무일과 대조한다.

**맛집 자료는 쓰지 않는다.** 실측해 보니 일정 정차지 52곳 중 맛집 이름과 맞는 것이
**하나도 없다**(식사 정차지는 `점심 · 전복죽·성게칼국수` 처럼 서술형이다). `FOOD.hours`
자체도 51곳 중 4곳뿐이고 `'월요일 정기 휴무'` `'09:00 영업 시작'` 처럼 형식이 제각각이다.

읽는 방법 (2026-08-28 실측으로 확인):

| 무엇 | 어디서 | 어떻게 |
|---|---|---|
| 그날 요일 | `D[i].dw` (`'화 · 동부'`) | 첫 글자 |
| 여는·닫는 시각 | `SPOT.open` | `/(\d{1,2}):(\d{2})\s*[~-]\s*(\d{1,2}):(\d{2})/` |
| 매주 휴무 요일 | `SPOT.off` | `/매주\s*([월화수목금토일])요일/` |

일정에 이름이 맞는 여행지는 17곳이고 그중 운영시간을 읽어낼 수 있는 것은 8곳이다.
못 읽는 9곳은 대부분 해변·오름의 `'상시 개방'` 이라 애초에 경고할 것이 없다.
전체 48곳 기준으로는 운영시간 26곳, 매주 휴무 4곳(유민미술관 화 · 김창열미술관 월 ·
제주현대미술관 월 · 비블리아 일)을 읽어낼 수 있다.

`'매월 첫째 월요일'` `'기상 악화 시 통제'` 처럼 요일 하나로 정리되지 않는 문구는
**경고하지 않는다.** 잘못된 경고는 없는 것만 못하다.

> 이 규칙을 지금 일정에 대 보니 **2일차(화요일) 14:00 유민미술관이 휴무일에 걸린다.**
> 편집기가 없었으면 못 찾았을 문제다.

> ※ 3일차는 화요일입니다. 유민미술관은 매주 화요일 휴무입니다.
> ※ 도착이 오후 6시 40분인데 만장굴은 오후 6시에 문을 닫습니다.

### 5.3 배 시간

`fix` 가 붙은 정차지는 그 시각을 지켜야 한다. 계산된 도착이 그보다 늦으면 알린다.

> ※ 진도항 도착이 오전 11시 20분으로 계산됩니다. 배는 오전 11시 5분까지 타야 합니다.

## 6. 저장과 내보내기

### 6.1 저장

편집 내용은 `localStorage` 에 담는다. 창을 닫아도 남는다.

**저장하는 것은 바뀐 값만이다** — 정차지 전체가 아니라 `{일차, 순번, 바뀐 필드}`.
그래야 배포판 일정이 나중에 바뀌어도 편집이 엉뚱한 곳에 붙지 않는다.

서비스워커가 새 `index.html` 을 받아도 `localStorage` 는 지워지지 않는다.
배포판 일정이 바뀌었는데 옛 편집이 남아 있으면 헷갈리므로, **저장할 때 그 시점의
배포판 일정 지문(정차지 이름을 이어 붙인 해시)을 함께 남기고, 지문이 다르면
편집을 자동으로 버린다.**

### 6.2 내보내기

`코드 복사` 는 바뀐 정차지들을 `D` 배열에 넣을 수 있는 자바스크립트 조각으로 만들어
클립보드에 담는다. 사람이 읽고 파일에 붙일 수 있는 형태여야 한다.

## 7. 만들지 않는 것

- **여러 사람이 함께 편집** — 서버가 필요하고 단일 파일 전제가 깨진다.
- **이동시간을 손으로 고치기** — 계산값을 덮어쓸 수 있게 하면 무엇이 계산이고 무엇이
  손댄 값인지 알 수 없게 된다.
- **경고를 무시 표시하기** — 편집자가 한 명뿐이라 필요 없다.
- **날짜 사이로 정차지 옮기기** — 하루 안에서만 옮긴다. 날짜를 넘나들면 경로선·핀 번호까지
  얽힌다. 필요해지면 그때 따로 다룬다.

## 8. 단계

한 번에 다 만들지 않는다. 1단계를 실제로 써 본 뒤 2단계를 얹는다.

**1단계 — 계산과 경고**
`#` 진입 · 편집 띠 · 시각과 머무는 시간 고치기 · 이동시간 계산과 캐시 ·
연쇄 재계산 · 하루 요약 배너 갱신 · 경고 세 종류 · 저장 · 코드 복사

**2단계 — 목록 손보기**
장소 바꾸기(검색·직접 입력) · 순서 바꾸기(끌기와 화살표) · 넣기·빼기

**맛집 51곳도 여행지 48곳과 함께 고를 수 있다.** 고르면 이름과 좌표가 들어가고,
**대표 메뉴(`FOOD.main`)를 함께 보여준다** — `범일분식 · 순대백반` 처럼. 어느 집인지는
이름보다 무엇을 먹는지로 기억되기 때문이다. 검색 결과 목록에도 같이 띄운다.

> 이렇게 하면 §5.2 의 제약이 풀린다. 지금은 식사 정차지 이름이 `점심 · 전복죽·성게칼국수`
> 같은 서술형이라 맛집 자료와 하나도 안 맞아 영업시간 경고를 걸 수 없다. 맛집을 골라
> 넣으면 이름이 자료와 맞아떨어지므로 **그때부터 맛집에도 휴무·영업시간 경고를 걸 수 있다.**
> `FOOD.hours` 는 51곳 중 4곳뿐이라 실효가 작지만, 고른 맛집에 `hours` 가 있으면 쓴다.

장소를 고르는 목록에서 **그날 요일이 정기 휴무인 곳은 보이되 고를 수 없게 한다.**
목록에서 아예 감추지 않는 이유는, 없는 것과 그날만 못 가는 것은 다르기 때문이다.
흐리게 표시하고 `그날(화요일) 휴무` 라고 이유를 붙인다. 요일을 알 수 없는 휴무 문구
(`'매월 첫째 월요일'` 등)는 §5.2 와 같이 잡지 않으므로 고를 수 있게 둔다.

1단계만으로도 "시각을 고치면 뒤가 따라 움직이고 무리한 곳이 보인다"는 핵심이 완성된다.
2단계는 그 위에 목록 자체를 주무르는 기능을 얹는 것이다.

## 9. 확인 기준

만들고 나서 이것들이 되어야 한다.

1. 편집기를 처음 열었을 때 계산된 시각이 **지금 일정과 모두 같다**(`stay` 자동 채우기가 맞다).
2. 3일차 첫 정차지 시각을 30분 늦추면 그날 뒤 정차지가 전부 30분 밀린다.
3. 머무는 시간을 30분 늘리면 그 뒤만 30분 밀리고 앞은 그대로다.
4. 인터넷을 끊어도 계산이 되고 값이 그럴듯하다.
5. 화요일에 유민미술관을 넣으면 휴무 경고가 뜬다.
6. 점심을 15시로 밀면 식사 타이밍 경고가 뜬다.
7. 진도항 도착을 배 시간 뒤로 밀면 배 경고가 뜬다.
8. `원래대로` 를 누르면 배포된 일정과 완전히 같아진다.
9. `코드 복사` 결과를 `index.html` 에 붙이면 편집한 그대로 나온다.
10. 회귀 점검 전 항목이 그대로 통과한다(편집기는 보기 화면을 건드리지 않는다).
